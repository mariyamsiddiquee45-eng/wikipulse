# Labeling guide

Labels are human judgments. They must not be generated by the pipeline or by an assistant.
The classifier is only as good as these decisions, so use the article and the evidence around
the spike.

## Classes

- **event**: a real-world occurrence explains the attention. Examples: a death, election,
  match result, accident, release, court decision, scandal.
- **recurring**: the same article gets attention on a cycle or as part of an expected series.
  Examples: annual holidays, yearly sports seasons, award ceremonies, "Deaths in YYYY".
- **noise**: no real-world cause is found. Bot traffic, a page move, maintenance, a data
  artifact, or a spike that cannot be tied to anything.

If you cannot decide, press `s` to skip. A skipped spike stays unlabeled and can appear in a
later session.

## Session

Run from the repository root in PowerShell.

```powershell
uv run --project pipeline wikipulse label --count 50 --labeler your-name
```

Keys:

- `e` event
- `n` noise
- `r` recurring
- `s` skip
- `q` quit

Every answer is appended to `labels/labels.csv` immediately, so quitting or losing the
terminal loses nothing. Start the next session with the same command; labeled spike ids are
skipped automatically.

The screen shows the date, article, spike type, views, baseline, z-score, peak ratio, rise
time, half-life, year-ago ratio, edit surge, a 30-day sparkline and the Wikipedia URL. Open
the URL when the context is not obvious.

## Target

- At least 300 labels.
- At least 60 are required by the trainer, but 60 is not enough for a trustworthy report.
- Cover all classes that actually occur. Do not force a class if it does not exist.
- Spread labels across the available days. The sampler is year-stratified; with a short
  archive it samples randomly across that window.
- If training later reports a missing class in validation, label more of that class.

## Train and publish

```powershell
uv run --project pipeline wikipulse train --model both
uv run --project pipeline wikipulse classify
uv run --project pipeline wikipulse export
```

`train` writes `data/models/classifier.joblib`, metadata and `data/reports/classifier.md`.
`classify` writes `class_probability` and `predicted_class` to every spike in range.
`export` puts those values on the site, and the Methods page reads the latest metrics.

Then rebuild and deploy:

```powershell
npm run build --prefix web
npx wrangler pages deploy web/dist --project-name wikipulse
```

## Commit the labels

`labels/labels.csv` is the only committed data file. Commit it when a batch is done:

```powershell
git add labels/labels.csv
git commit -m "test(ml): add a batch of human labels"
```

Keep the file in version control so the label history is reproducible.
